# Phase 0: ISO/IEC 13818-1 (ITU-T H.222.0) for the KLV write path

> Phase 0 record. Where this document and [DECISIONS.md](DECISIONS.md) disagree (sections 1 and 3 there), DECISIONS.md wins. Source paths `specs/src/...` refer to the workspace copy of the official documents, which are not redistributed here.

Topic `iso13818`. Scope: everything a conformant TS muxer/injector must do to add a KLV metadata stream (sync 0x15/0xFC or async 0x06/0xBD) to an existing program, and later to mux from elementary streams. MISB-specific values (ST 1402.2) are cross-referenced but owned by the `st1402` topic.

Notes on the source text:

- The PDF could not be rendered here (no poppler). Field widths of the column-split syntax tables (Tables 2-84, 2-87, 2-89, 2-108) were rebuilt from the order of the extracted columns and cross-checked against ST 1402.2 Appendix B (descriptor_length 9, five-byte cell header) and against FFmpeg and GStreamer. ## 2. Rules

Implementer names: `mpegts::mux TsWriter` (TS packets, CC, adaptation fields), `PesWriter` (PES headers, packetisation), `ProgramTables` (PAT/PMT, descriptors, CRC, versions), `metadata cells` (AU wrapper), `Injector` (pass-through plus insertion), `Muxer (later)` (elementary-stream muxer with PCR generation), `misb::mux` (scheduler, anchors), `checker` (conformance checker in `mpegts`).

### TS packet layer (2.4.3.2, 2.4.3.3)

- **R-ISO13818-001** (ts_len) Every TS packet is exactly 188 bytes (192/204-byte variants are a container concern of the caller, not of the TS packet).
  - Implements: mpegts::mux TsWriter; checker. Source: H.222.0 (10/2014) 2.4.3.
  - Quote: "Transport stream packets shall be 188 bytes long." (specs/src/H.222.0-201410.txt:1728)

- **R-ISO13818-002** (sync) Byte 0 of every packet is the sync_byte 0x47.
  - Implements: mpegts::mux TsWriter; checker. Source: H.222.0 (10/2014) 2.4.3.3.
  - Quote: "The sync_byte is a fixed 8 -bit field whose value is '0100 0111' (0x47)." (specs/src/H.222.0-201410.txt:1763)

- **R-ISO13818-003** (tei) Write transport_error_indicator = 0 in every generated packet. Pass-through packets keep their TEI unchanged (never clear a TEI set upstream).
  - Implements: mpegts::mux TsWriter; mpegts::mux Injector. Source: H.222.0 (10/2014) 2.4.3.3.
  - Quote: "When set to '1' this bit shall not be reset to '0' unless the bit value(s) in error have been corrected." (specs/src/H.222.0-201410.txt:1767)

- **R-ISO13818-004** (pusi_pes) On a PES-carrying PID, payload_unit_start_indicator = 1 exactly in the packet whose payload begins with the first byte of a PES packet; 0 in every continuation packet. A PES packet always starts at payload byte 0.
  - Implements: mpegts::mux TsWriter; mpegts::mux PesWriter; checker. Source: H.222.0 (10/2014) 2.4.3.3.
  - Quote: "a '1' indicates that the payload of this transport stream  packet will commence with the first byte of a PES packet and a '0' indicates no PES packet shall start in this transport stream  packet." (specs/src/H.222.0-201410.txt:1773)

- **R-ISO13818-005** (pusi_one) A packet with PUSI = 1 starts one and only one PES packet; this applies to stream_type 0x06 too. After a PES ends inside a packet, the rest of that packet is adaptation-field stuffing, never the start of the next PES.
  - Implements: mpegts::mux PesWriter; checker. Source: H.222.0 (10/2014) 2.4.3.3.
  - Quote: "If the payload_unit_start_indicator is set to '1' , then one and only one PES packet starts in this transport stream  packet. This also applies to private streams of stream_type 6" (specs/src/H.222.0-201410.txt:1774)

- **R-ISO13818-006** (pusi_sec) On a PSI PID, PUSI = 1 when a section starts in the packet, and then the first payload byte is the pointer_field; PUSI = 0 and no pointer_field otherwise.
  - Implements: mpegts::mux ProgramTables; checker. Source: H.222.0 (10/2014) 2.4.3.3.
  - Quote: "if the transport stream  packet carries the first byte of a section, the payload_unit_start_indicator value shall be '1', indicating that the first byte of the payload of this transport stream  packet carries the pointer_field." (specs/src/H.222.0-201410.txt:1777)

- **R-ISO13818-007** (tsc) transport_scrambling_control = '00' in every generated packet; the TS header and adaptation field are never scrambled. The injector refuses scrambled input programs (it cannot rewrite their PES).
  - Implements: mpegts::mux TsWriter; mpegts::mux Injector. Source: H.222.0 (10/2014) 2.4.3.3, Table 2-4.
  - Quote: "The transport stream  packet header, and the adaptation field when present, shall not be scrambled. In the case of a null packet the value of the transport_scrambling_control field shall be set to '00'" (specs/src/H.222.0-201410.txt:1809)

- **R-ISO13818-008** (afc00) Never write adaptation_field_control = '00' (reserved; decoders discard such packets). Use '01' payload only, '10' adaptation field only, '11' both.
  - Implements: mpegts::mux TsWriter; checker. Source: H.222.0 (10/2014) 2.4.3.3, Table 2-5.
  - Quote: "decoders shall discard transport stream  packets with the adaptation_field_control field set to a value of '00'. In the case of a null packet the value of the adaptation_field_control shall be set to '01'." (specs/src/H.222.0-201410.txt:1827)

- **R-ISO13818-009** (cc_inc) continuity_counter is kept per PID: 4 bits, +1 for each packet of that PID, wrapping 15 -> 0.
  - Implements: mpegts::mux TsWriter; checker. Source: H.222.0 (10/2014) 2.4.3.3.
  - Quote: "The continuity_counter is a 4 -bit field incrementing with each transport stream  packet with the same PID. The continuity_counter wraps around to 0 after its maximum value." (specs/src/H.222.0-201410.txt:1829)

- **R-ISO13818-010** (cc_noinc) A packet without payload (adaptation_field_control '10') repeats the CC of the previous packet of that PID instead of incrementing it.
  - Implements: mpegts::mux TsWriter; checker. Source: H.222.0 (10/2014) 2.4.3.3.
  - Quote: "The continuity_counter shall not be incremented when the adaptation_field_con trol of the packet equals '00' or '10'." (specs/src/H.222.0-201410.txt:1830)

- **R-ISO13818-011** (dup_cc) Duplicate packets: at most two consecutive packets of a PID may share a CC, both with payload (AFC '01' or '11'). We never generate duplicates; the injector passes input duplicates through and the checker accepts them.
  - Implements: mpegts::mux Injector; checker. Source: H.222.0 (10/2014) 2.4.3.3.
  - Quote: "The duplicate packets shall have the same continuity_counter value as the original packe t and the adaptation_field_control field shall be equal to '01' or '11'." (specs/src/H.222.0-201410.txt:1833)

- **R-ISO13818-012** (dup_bytes) A duplicate is byte-identical to the original except that any PCR in it carries a valid (re-sampled) value. The checker treats a same-CC packet that differs elsewhere as a CC error.
  - Implements: checker. Source: H.222.0 (10/2014) 2.4.3.3.
  - Quote: "In duplicate packets each byte of the original packet shall be duplicated, with the exception that in the program clock reference fields, if present, a valid value shall be encoded." (specs/src/H.222.0-201410.txt:1834)

- **R-ISO13818-013** (cc_disc) A CC jump is legal only in a packet whose discontinuity_indicator = 1. Generated PIDs are always continuous; when the injector takes over an existing PID (ExistingKlv::Replace on the same PID) it continues that PID's CC sequence.
  - Implements: mpegts::mux TsWriter; mpegts::mux Injector; checker. Source: H.222.0 (10/2014) 2.4.3.3.
  - Quote: "The continuity counter may be discontinuous when the discontinuity_indicator is set to '1' (refer to 2.4.3.4)." (specs/src/H.222.0-201410.txt:1839)

- **R-ISO13818-014** (n_bytes) Payload length N = 184 minus the adaptation_field() length (including its length byte), so header + adaptation field + payload is always 188 bytes.
  - Implements: mpegts::mux TsWriter; checker. Source: H.222.0 (10/2014) 2.4.3.3.
  - Quote: "The number of data_bytes, N, is specified by 184 minus the number of bytes in the adaptation_field(), as described in 2.4.3.4 below." (specs/src/H.222.0-201410.txt:1844)


### PIDs and null packets (2.4.1, 2.4.3.3, Table 2-3)

- **R-ISO13818-015** (pid_assign) Generated elementary, PMT and PCR PIDs are in 0x0010-0x1FFE. 0x0000 PAT, 0x0001 CAT, 0x0002 TSDT, 0x0003 IPMP, 0x0004 adaptive streaming information, 0x0005-0x000F reserved, 0x1FFF null.
  - Implements: mpegts::mux ProgramTables; mpegts::mux Injector; checker. Source: H.222.0 (10/2014) 2.4.3.3, Table 2-3.
  - Quote: "May be assigned as network_PID, Program_map_PID, elementary_PID, or for other purposes" (specs/src/H.222.0-201410.txt:1804)

- **R-ISO13818-016** (pcr_pids) PCRs may only appear on PIDs 0x0000, 0x0001 and 0x0010-0x1FFE (never on 0x0002-0x000F or 0x1FFF). Our muxer puts PCR on an elementary or dedicated PID in 0x0010-0x1FFE.
  - Implements: mpegts::mux Muxer (later); checker. Source: H.222.0 (10/2014) Table 2-3 NOTE 1.
  - Quote: "The transport packets with PID values 0x0000, 0x0001, and 0x0010 -0x1FFE are allowed to carry a PCR." (specs/src/H.222.0-201410.txt:1806)

- **R-ISO13818-017** (null_pusi) Null packet: PID 0x1FFF, PUSI = 0.
  - Implements: mpegts::mux TsWriter; checker. Source: H.222.0 (10/2014) 2.4.3.3.
  - Quote: "For null packets the payload_unit_start_indicator shall be set to '0'." (specs/src/H.222.0-201410.txt:1782)

- **R-ISO13818-018** (null_cc) Null packet CC is undefined (the checker ignores it) and its 184 data bytes may hold any value; we write CC = 0 and 0xFF bytes.
  - Implements: mpegts::mux TsWriter; checker. Source: H.222.0 (10/2014) 2.4.3.3.
  - Quote: "In the case of a null packet the value of th e continuity_counter is undefined." (specs/src/H.222.0-201410.txt:1840)

- **R-ISO13818-019** (null_remux) Null packets may be added or removed by any remultiplexer, so their payload carries nothing. This is what allows Cbr { replace_nulls } to overwrite them with KLV or PSI packets.
  - Implements: mpegts::mux Injector. Source: H.222.0 (10/2014) 2.4.1.
  - Quote: "Null packets are intended for padding of transport stream s. They may be inserted or deleted by re -multiplexing processes" (specs/src/H.222.0-201410.txt:1241)

- **R-ISO13818-020** (one_es_per_pid) One PID carries exactly one elementary stream: a KLV stream gets its own PID, never shared with video or with another metadata stream.
  - Implements: mpegts::mux ProgramTables; mpegts::mux Injector. Source: H.222.0 (10/2014) 2.4.1.
  - Quote: "Transport stream packets of one PID value carry data of one and only one elementary stream." (specs/src/H.222.0-201410.txt:1225)


### Adaptation field and stuffing (2.4.3.4, 2.4.3.5, Table 2-6)

- **R-ISO13818-021** (af_len) adaptation_field_length is 0..182 when AFC = '11' and exactly 183 when AFC = '10'.
  - Implements: mpegts::mux TsWriter; checker. Source: H.222.0 (10/2014) 2.4.3.5.
  - Quote: "When the adaptation_field_control va lue is '11', the value of the adaptation_field_length shall be in the range 0 to 182. When the adaptation_field_control value is '10', the value of the adaptation_field_length shall be  183." (specs/src/H.222.0-201410.txt:1916)

- **R-ISO13818-022** (af_zero) adaptation_field_length = 0 is the one-byte stuffing form (no flags byte follows). Length 1 is a flags byte only (0x00); length n >= 2 is the flags byte plus n - 1 stuffing bytes.
  - Implements: mpegts::mux TsWriter. Source: H.222.0 (10/2014) 2.4.3.5.
  - Quote: "The value '0' is for inserting a single stuffing byte in the adaptation field of a transport stream packet." (specs/src/H.222.0-201410.txt:1915)

- **R-ISO13818-023** (af_stuff_only) A TS packet carrying PES data that has fewer PES bytes left than payload room is filled by enlarging its adaptation field. Never pad a PES-carrying packet with payload bytes.
  - Implements: mpegts::mux TsWriter; mpegts::mux PesWriter; checker. Source: H.222.0 (10/2014) 2.4.3.5.
  - Quote: "This is the only method of stuffing allowed for transport stream packets carrying PES packets." (specs/src/H.222.0-201410.txt:1925)

- **R-ISO13818-024** (stuff_byte) Adaptation field stuffing bytes are 0xFF.
  - Implements: mpegts::mux TsWriter. Source: H.222.0 (10/2014) 2.4.3.5.
  - Quote: "This is a fixed 8 -bit value equal to '1111 1111' that can be inserted by the encoder." (specs/src/H.222.0-201410.txt:2378)

- **R-ISO13818-025** (pcr_field) PCR = program_clock_reference_base (33 bits) + 6 reserved bits ('111111') + program_clock_reference_extension (9 bits); its value is the T-STD arrival time of the byte holding the last bit of the base, i.e. byte 10 of a packet whose adaptation field starts with the PCR.
  - Implements: mpegts::mux Muxer (later); checker. Source: H.222.0 (10/2014) 2.4.3.5.
  - Quote: "The PCR indicates the intended time of arrival of the byte containing the last bit of the program_clock_reference_base at the input of the system target decoder." (specs/src/H.222.0-201410.txt:2085)

- **R-ISO13818-026** (opcr_with_pcr) OPCR is only written in a packet that also has a PCR. We never write OPCR.
  - Implements: mpegts::mux TsWriter; checker. Source: H.222.0 (10/2014) 2.4.3.5.
  - Quote: "The OPCR field shall be coded only in transport stream packets in which the PCR field is present." (specs/src/H.222.0-201410.txt:2092)

- **R-ISO13818-027** (opcr_keep) A multiplexer never modifies an OPCR: pass-through packets keep it byte-exact (including the Cbr modes).
  - Implements: mpegts::mux Injector. Source: H.222.0 (10/2014) 2.4.3.5.
  - Quote: "The OPCR field shall not be modified by any multiplexor or decoder." (specs/src/H.222.0-201410.txt:2107)

- **R-ISO13818-028** (tpd_len) transport_private_data must fit inside the adaptation field. We never write it; the checker verifies input.
  - Implements: checker. Source: H.222.0 (10/2014) 2.4.3.5.
  - Quote: "The number of private_data bytes shall be such that private data does not extend beyond t he adaptation field." (specs/src/H.222.0-201410.txt:2127)


### Discontinuities and random access (2.4.3.5)

- **R-ISO13818-029** (di_tb) A system time-base discontinuity is signalled with discontinuity_indicator = 1 in the PCR_PID packet carrying the first PCR of the new time base (it may also be set in earlier packets of that PID, then continuously up to it). The injector never creates one; it passes input ones through and treats them as an anchor break.
  - Implements: mpegts::mux Injector; misb::mux; checker. Source: H.222.0 (10/2014) 2.4.3.5.
  - Quote: "The discontinuity_indicator shall be set to '1' in the packet in which the system time -base discontinuity occurs." (specs/src/H.222.0-201410.txt:1936)

- **R-ISO13818-030** (di_two_pcr) At least two PCRs of the new time base precede the next time-base discontinuity.
  - Implements: mpegts::mux Muxer (later); checker. Source: H.222.0 (10/2014) 2.4.3.5.
  - Quote: "no fewer than two PCRs for the new system time -base shall be received before anoth er system time -base discontinuity can occur." (specs/src/H.222.0-201410.txt:1941)

- **R-ISO13818-031** (di_pts) No packet with a PTS/DTS of the new time base may arrive before the discontinuity, and none of the old time base after it: inserted sync KLV is stamped in the time base that is current at its insertion point, and an AU whose PTS belongs to the other side of a discontinuity is dropped or re-anchored, never sent across it.
  - Implements: mpegts::mux Injector; misb::mux; checker. Source: H.222.0 (10/2014) 2.4.3.5.
  - Quote: "the first byte of a transport stream packet which contains a PTS or DTS which refers to the new system time -base shall not arrive at the input of the T -STD." (specs/src/H.222.0-201410.txt:1944)

- **R-ISO13818-032** (di_cc) On a PID that is not the PCR_PID, discontinuity_indicator = 1 permits a CC jump in that packet.
  - Implements: checker. Source: H.222.0 (10/2014) 2.4.3.5.
  - Quote: "When the discontinuity state is true in any transport stream packet of a PID not designated as a PCR_PID, the continuity_counter in that packet may be discontinuous with respect to the previous transport stream packet of the same PID." (specs/src/H.222.0-201410.txt:1949)

- **R-ISO13818-033** (di_three) On non-PCR PIDs the discontinuity_indicator is never 1 in three consecutive packets.
  - Implements: checker. Source: H.222.0 (10/2014) 2.4.3.5.
  - Quote: "may be set to '1' in the next transport stream packet of that same PID, but shall not be set to '1' in three consecutive transport stream packet of that same PID." (specs/src/H.222.0-201410.txt:1957)

- **R-ISO13818-034** (di_access) After a CC discontinuity on an ES PID, the next ES byte starts an access point (for our metadata PID: a PES whose first cell starts an AU).
  - Implements: mpegts::mux Injector; checker. Source: H.222.0 (10/2014) 2.4.3.5.
  - Quote: "the first by te of elementary stream data in a transport stream packet of the same PID shall be the first byte of an elementary stream access point." (specs/src/H.222.0-201410.txt:2020)

- **R-ISO13818-035** (di_dup_loss) In the discontinuity state a second same-CC packet may be discarded by a receiver, so it must not carry needed data.
  - Implements: checker. Source: H.222.0 (10/2014) 2.4.3.5.
  - Quote: "A transport stream shall not be constructed in such a way that di scarding such a packet will cause the loss of PES packet payload data or transport stream section data." (specs/src/H.222.0-201410.txt:2029)

- **R-ISO13818-036** (psi_disc) After a discontinuity_indicator in a PSI packet, a PMT version jump is only allowed via an empty PMT (section_length 13) followed by the full PMT. We never use this; the checker recognises it.
  - Implements: checker. Source: H.222.0 (10/2014) 2.4.3.5.
  - Quote: "At the occurrence of such a discontinuity, a version of the TS_program_map_sections of the appropriate program shall be sent with section_length = = 13" (specs/src/H.222.0-201410.txt:2033)

- **R-ISO13818-037** (rai) random_access_indicator = 1 promises that the next PES starting on this PID contains an elementary stream access point (defined only for video, audio and text formats). We do not set it on metadata PIDs (see Decisions).
  - Implements: mpegts::mux PesWriter; checker. Source: H.222.0 (10/2014) 2.4.3.5.
  - Quote: "when the bit is set to '1', the next PES packet to start in the payload of transport stream packets with the current PID shall contain  an elementary stream access point" (specs/src/H.222.0-201410.txt:2043)

- **R-ISO13818-038** (rai_pcr) On the PCR_PID, random_access_indicator = 1 only in a packet that carries a PCR.
  - Implements: mpegts::mux Muxer (later); checker. Source: H.222.0 (10/2014) 2.4.3.5.
  - Quote: "In the PCR_PID the random_access_indicator may only be set to '1' in a transport stream packet containing the PCR fields." (specs/src/H.222.0-201410.txt:2048)


### System clock and PCR (2.4.2.1, 2.4.2.2, 2.7.2)

- **R-ISO13818-039** (stc_freq) The program clock is 27 MHz +- 810 Hz with drift at most 0.075 Hz/s. The muxer derives PCR from the caller's clock; the checker measures PCR against byte positions in CBR streams.
  - Implements: mpegts::mux Muxer (later); checker. Source: H.222.0 (10/2014) 2.4.2.1.
  - Quote: "27 000 000 - 810 ≤ system_clock_frequency ≤ 27 000 000 + 810 rate of change of system_clock_frequenc y with time ≤ 75 × 10-3 Hz/s" (specs/src/H.222.0-201410.txt:1339)

- **R-ISO13818-040** (pcr_tol) PCR tolerance (maximum inaccuracy of a received PCR, excluding network jitter) is +-500 ns (line 1398 reads 'The PCR tolerance is [+-] 500 ns', the +- extracted as a symbol-font glyph). Generated PCRs are exact to the byte position; pass-through and Cbr { replace_nulls } never move a PCR-bearing packet, so they add no PCR error.
  - Implements: mpegts::mux Muxer (later); mpegts::mux Injector; checker. Source: H.222.0 (10/2014) 2.4.2.2.
  - Quote: "The PCR tolerance is defined as the maximum inaccuracy allowed in received PCRs." (specs/src/H.222.0-201410.txt:1396)

- **R-ISO13818-041** (pcr_where) PCRs travel in the adaptation field of packets on the PCR_PID named in the program's PMT. Injection never changes the PCR_PID.
  - Implements: mpegts::mux Injector; mpegts::mux Muxer (later); checker. Source: H.222.0 (10/2014) 2.4.2.1.
  - Quote: "are carried in the adaptation field of the transport stream  packets with a PID value equal to the PCR_PID defined in the" (specs/src/H.222.0-201410.txt:1333)

- **R-ISO13818-042** (pcr_code) PCR_base = (27 MHz time / 300) mod 2^33 and PCR_ext = (27 MHz time) mod 300 (equations 2-1 to 2-3; the extracted equations are garbled, the prose is not).
  - Implements: mpegts::mux Muxer (later); checker. Source: H.222.0 (10/2014) 2.4.2.2.
  - Quote: "The PCR field (see equation 2 -1) is encoded in two parts: one, in units of the period of 1/300 times the system clo ck frequency, called program_clock_reference_base" (specs/src/H.222.0-201410.txt:1361)

- **R-ISO13818-043** (pcr_rate) Byte arrival times between two PCRs of a program are interpolated linearly: transport rate = bytes between the last base bits of two successive PCRs / PCR difference. The checker uses this to time every packet; VBR insertion simply raises the rate of that PCR interval.
  - Implements: checker. Source: H.222.0 (10/2014) 2.4.2.2.
  - Quote: "the transport rate is determined as the number of bytes in the transport stream  between the bytes containing the last bit of two successive program_clock_reference_base fields of the same program divided  by the difference between the time values" (specs/src/H.222.0-201410.txt:1376)

- **R-ISO13818-044** (pcr_multiprog) With several programs on independent time bases, a variable-rate TS has no consistent T-STD schedule. VBR insertion into a multi-program TS therefore breaks the other programs' timing; the injector warns and recommends Cbr { replace_nulls } there.
  - Implements: mpegts::mux Injector; checker. Source: H.222.0 (10/2014) 2.4.2.2.
  - Quote: "it is not possible to construct a consistent T -STD delivery schedule for an enti re transport stream  when that transport stream  contains multiple programs with independent time bases and the rate of the transport stream  is variable." (specs/src/H.222.0-201410.txt:1406)

## 3. Byte layouts

All multi-byte fields are big-endian, most significant bit first ("bslbf"/"uimsbf", 2.2.6). Reserved bits are 1 (R-ISO13818-103). Values in the last column are what we write; "var" means computed.

### 3.1 TS packet header (4 bytes) (R-ISO13818-001 to R-ISO13818-014)

| Bits | Field | Value we write |
|---|---|---|
| 8 | sync_byte | 0x47 |
| 1 | transport_error_indicator | 0 (pass-through: unchanged) |
| 1 | payload_unit_start_indicator | 1 on the packet that starts a PES / a section, else 0 |
| 1 | transport_priority | 0 |
| 13 | PID | var (0x1FFF for null) |
| 2 | transport_scrambling_control | '00' |
| 2 | adaptation_field_control | '01' payload only, '11' AF + payload, '10' AF only (never '00') |
| 4 | continuity_counter | per PID, +1 per packet with payload, unchanged on AFC '10' |

Byte 1 = `(TEI << 7) | (PUSI << 6) | (prio << 5) | (PID >> 8)`, byte 2 = `PID & 0xFF`, byte 3 = `(TSC << 6) | (AFC << 4) | CC`.

### 3.2 Adaptation field forms we write (R-ISO13818-021, R-ISO13818-022, R-ISO13818-023, R-ISO13818-025)

| Need | Bytes after the 4-byte header | Payload room |
|---|---|---|
| 1 byte of stuffing | `00` | 183 |
| 2 bytes of stuffing | `01 00` | 182 |
| n >= 3 bytes of stuffing | `n-1  00  FF x (n-2)` | 184 - n |
| PCR only (no stuffing) | `07 10` + 6 PCR bytes (length 7, flags 0x10, 33-bit base, '111111', 9-bit ext; bytes below) | 176 |
| PCR + k stuffing bytes | `07+k 10 <6 PCR bytes> FF x k` | 176 - k |
| AF only (AFC '10') | `B7 <flags> ... FF` (length 183) | 0 |

PCR bytes for base `b` (33 bits) and extension `e` (9 bits): `b>>25`, `b>>17`, `b>>9`, `b>>1`, `((b & 1) << 7) | 0x7E | (e >> 8)`, `e & 0xFF`. The PCR value is the T-STD arrival time of byte 10 of the packet (the byte holding the last base bit) when the PCR is the first AF field (R-ISO13818-025); `b = (t27M / 300) mod 2^33`, `e = t27M mod 300` (R-ISO13818-042).

### 3.3 Null packet (R-ISO13818-017, R-ISO13818-018, R-ISO13818-007, R-ISO13818-008)

`47 1F FF 10` followed by 184 bytes `FF` (PUSI 0, TSC '00', AFC '01', CC written as 0).

### 3.4 Section packetisation (R-ISO13818-006, R-ISO13818-074, R-ISO13818-073, R-ISO13818-075)

First packet of a section: PUSI 1, payload = `pointer_field (00)` + section bytes; continuation packets: PUSI 0, section bytes; after the section's last byte, fill the packet payload with `FF`. AFC '01'. One section is finished before the next starts on the same PID.

## 4. Decisions

D-ISO13818-01. **PMT descriptors for sync KLV (0x15/0xFC).** ES loop, in this order: registration_descriptor "KLVA" (on by default, option to omit), metadata_descriptor, metadata_STD_descriptor. Program loop: nothing added by default; metadata_pointer_descriptor only when configured.
- metadata_descriptor: 13818 states it is "included in the PMT in the descriptor loop for the elementary stream that carries the metadata service" (R-ISO13818-118); ST 1402-15/-16 make it a "shall". Always written, one per service.
- metadata_STD_descriptor: 13818 has no sentence requiring its presence, but the metadata T-STD takes Rx_n and BS_n only from it (R-ISO13818-158, R-ISO13818-159); without it the model is undefined. ST 1402-17 requires exactly one per metadata stream. Always written, exactly one per stream.
- registration_descriptor on a 0x15 stream: standard silent (13818 neither requires nor forbids it) (R-ISO13818-108). The patched FFmpeg writes it for every KLV stream; demuxers that identify KLV only by a "KLVA" registration (older FFmpeg, other tools) then still recognise the stream. FFmpeg's demuxer also recognises KLV from the metadata_descriptor alone (`specs/ref/ff_mpegts.c` METADATA_DESCRIPTOR case). Written by default; the `st1402` topic may override.
- metadata_pointer_descriptor: 13818 requires one pointer descriptor per service only when pointer descriptors are used to associate services with content (R-ISO13818-111); it is meant for metadata in another program/TS or on the Internet (R-ISO13818-110). ST 1402 does not require it, neither FFmpeg nor GStreamer writes it. Optional (config), program loop, MPEG_carriage_flags 0, program_number of the same program.

D-ISO13818-02. **Async KLV (0x06/0xBD).** ES loop: registration_descriptor "KLVA" only. No metadata descriptors: async KLV is a "private means" (R-ISO13818-131); 13818 would allow metadata descriptors but nothing requires them, and ST 1402-25 asks for the registration descriptor. FFmpeg and GStreamer write exactly this.

D-ISO13818-03. **metadata_service_id.** 13818 requires uniqueness across the whole TS (R-ISO13818-128); the value itself: standard silent. The injector collects the service ids of all metadata_descriptors and pointer descriptors in all PMTs (and of cells seen on existing 0xFC PIDs) and uses the lowest unused value, 0x00 when free (ST 1402 Appendix B sample value). With ExistingKlv::Replace on the same PID, the old service id is reused.

D-ISO13818-04. **metadata_STD_descriptor values.** Standard silent on values ("determined by encoder" in ST 1402.2 Appendix B). Defaults, both configurable:
- metadata_input_leak_rate = 250000 (Rx_n = 100 Mbit/s). TB_n is 512 bytes and receives whole 188-byte packets at the transport rate R (R-ISO13818-147). With k metadata packets back to back (which is how the injector inserts a PES before a video frame), TB fullness peaks at about 188k - (k-1) x 188 x Rx_n / R; it stays <= 512 for every k exactly when Rx_n >= R (for k <= 2 it is always fine). 100 Mbit/s exceeds the transport rate of ST 1402 class 1/2 streams by a wide margin, so injection never overflows TB_n. If the measured input rate exceeds Rx_n, the injector spaces metadata packets so the formula holds (and the checker verifies). The field allows up to 0x3FFFFF (about 1.68 Gbit/s). Neither reference writes this descriptor, so there is no prior art to follow.
- metadata_buffer_size = 128 (131072 bytes). B_n holds every metadata PES byte from arrival until its PTS (D-ISO13818-05); arrival is at most 1 s before the PTS (R-ISO13818-157), so 128 KiB covers 1 s of lead at up to about 1 Mbit/s of metadata, far above ST 0601 rates (a 1 kB packet at 60 Hz is 0.5 Mbit/s). It must also be at least the PES bytes of the largest AU. File mode may pre-scan the source and raise the value before the first PMT; live mode keeps the configured value and the injector never exceeds it (it inserts closer to the PTS or applies the drop policy).
- metadata_output_leak_rate = 0 (R-ISO13818-127; ST 1402 recommends 0).

D-ISO13818-05. **Metadata B_n accounting in the checker.** 2.12.10 says "the metadata enters buffer B_n" without saying whether PES headers do. The checker follows the audio rule of 2.4.2.3 (R-ISO13818-148): all PES bytes (PES header, cell headers, cell data) enter B_n at Rx_n, and at the PTS all bytes of the PES packets that carry the AU are removed (R-ISO13818-160). This is conservative (it can only overstate fullness). Underflow = any byte of an AU (any fragment) not in B_n at its PTS. A fragmented AU is removed when the PTS is reached; all its PES carry that PTS.

D-ISO13818-06. **Sync PES packing.** One AU per PES by default. An AU larger than 65522 bytes is fragmented into cells of at most 65522 data bytes, one cell per PES, every PES carrying the AU's PTS (R-ISO13818-138, R-ISO13818-135), sent consecutively. Several AUs share a PES only if they have the same PTS (option for several services in one stream), never AUs with different PTS (R-ISO13818-134). A cell never spans two PES packets (R-ISO13818-133). Same as FFmpeg except its cell limit is 65517 (it reserves room for a DTS that metadata never has).

D-ISO13818-07. **Cell header values.** sequence_number: one counter per PID starting at 0, +1 per cell, mod 256, across services (R-ISO13818-140); when taking over an existing 0xFC PID, continue from the last input value + 1 so receivers see no loss. random_access_indicator: 1 on '11' and '10' cells (every ST 0601 packet is self-contained, so its first byte is an entry point), 0 on '00' and '01' cells, which cannot be entry points by definition (R-ISO13818-142). FFmpeg writes 1 on every cell including middle and last fragments (deviation in meaning). decoder_config_flag 0, reserved '1111'.

D-ISO13818-08. **Sync PES header values** (layout 3.8). data_alignment_indicator: 13818 defines alignment types only for video and audio (R-ISO13818-053), so for metadata it is standard silent. We write 1 when the PES's first cell starts an AU ('11' or '10') and 0 otherwise, mirroring the async rule ST 1402-20/-21; every metadata PES is in any case aligned to a cell. FFmpeg writes 1 on every data PES. original_or_copy: standard silent on which value to use; we write 1 (original) like GStreamer; FFmpeg writes 0; no decoder uses it (R-ISO13818-054). No DTS ever (R-ISO13818-067). No PES header stuffing.

D-ISO13818-09. **Async PES header values** (layout 3.9). PTS_DTS_flags '00' (ST 1402-22), DAI per ST 1402-20/-21, PES_packet_length always non-zero (R-ISO13818-051), so a KLV packet larger than 65532 bytes is split over several PES packets (DAI 0 on the continuations). One KLV packet per PES by default. 2.7.5 asks for a PTS on the first access unit of each elementary stream (R-ISO13818-068); for private data 13818 defines no access unit and its STD stops at the demultiplexer (R-ISO13818-163), so we read that rule as not applying and follow ST 1402-22.

D-ISO13818-10. **TS packetisation of inserted PES.** PUSI 1 on the first packet; AFC '01'; the last packet of a PES uses AF stuffing (R-ISO13818-023); a new PES always starts in a new packet (R-ISO13818-005). random_access_indicator in the adaptation field is not set on metadata PIDs (standard silent for metadata): 13818 defines elementary stream access points only for video, audio and text (R-ISO13818-037), the cell-level random_access_indicator carries this information for metadata, and an extra adaptation field costs two bytes per PES. GStreamer does not set it for KLV; FFmpeg sets it when the packet is flagged as a key frame. transport_priority 0, elementary_stream_priority_indicator 0. CC of a new PID starts at 0.

D-ISO13818-11. **PID selection.** Standard silent beyond the reserved ranges. Fixed by configuration, or automatic: the lowest PID above the target program's highest elementary PID that is unused anywhere in the input (PAT, every PMT including PCR_PIDs, CAT, NIT PID, and every PID observed so far), falling back to the lowest unused PID >= 0x0020; never 0x0000-0x001F (13818 reserves 0x0000-0x000F, R-ISO13818-015; 0x0010-0x001F are DVB SI PIDs by convention outside 13818), never 0x1FFB (ATSC base PID, convention outside 13818) or 0x1FFF, and never a PID whose low byte is 0x47 (R-ISO13818-173). Grouping near the program's PIDs follows G.1.3 (R-ISO13818-174). If a later input PMT starts using our PID, the injector reports a collision (it does not silently move the stream).

D-ISO13818-12. **PMT rewriting by the injector.** Only the PMT PID(s) of the target program are rewritten; the PAT is passed through untouched (R-ISO13818-086, R-ISO13818-087).
- The whole PMT PID is re-sectioned: every section on it is parsed; only the target program's section is modified; other programs' sections and private sections sharing the PID are re-emitted byte-identical, in input order (R-ISO13818-075).
- Version: output version = (input version + 1 + k) mod 32, where k counts our own definition changes since start (normally 0: the KLV entry is present from the first output PMT and stays, also in live mode where data may start later; a sparse or idle ES is legal). Every input version step is then exactly one output step (R-ISO13818-093). Standard silent on the starting value; the +1 makes the rewritten table distinguishable from the input's to receivers that cache by version.
- current_next_indicator is preserved: input "next" sections (cni 0) are transformed with the same mapping, so they become current at the same moment (R-ISO13818-094).
- CRC recomputed (R-ISO13818-100); if the grown section exceeds section_length 1021 / program definition 1016 bytes, injection fails before any output for that program (R-ISO13818-091, R-ISO13818-092).
- Emitted at the positions of the input PMT packets (keeping the input's repetition cadence, R-ISO13818-076); extra packets needed by a longer section go right after them (Vbr) or into following null packets (Cbr), or the injector fails (Cbr, no headroom). The PMT PID's CC is renumbered continuously on output.
- ExistingKlv::Replace: the old KLV ES entry is removed and the new one added in the same version step; reusing the old PID continues its CC (and cell sequence number), using a new PID drops all packets of the old one from the switch point.

D-ISO13818-13. **First metadata packet after the PMT.** Metadata on the new PID is emitted only after the first output PMT that lists it, and not before that section can have left B_sys (R-ISO13818-088): t(first KLV byte) >= t(last PMT byte) + 8 x section_bytes / Rsys + 4 ms, with Rsys = max(80 000, 8 x transport_rate / 500) bit/s (R-ISO13818-154, R-ISO13818-171). Before that, receivers ignore the PID (R-ISO13818-089). AUs due earlier are delayed within their 1 s window or dropped (counted).

D-ISO13818-14. **Sync insertion window.** Every byte of an AU arrives at most 1 s before its PTS (R-ISO13818-157) and the whole AU reaches B_n before its PTS (R-ISO13818-160). The plan's placement "immediately before the first TS packet of the video frame with the same PTS" satisfies the second condition (that frame must arrive before its DTS <= PTS) but not always the first: AVC and HEVC video may lead its decode time by up to 10 s (R-ISO13818-164, R-ISO13818-168) and PTS exceeds DTS by the reorder delay. The 10 ms and 1 ms margins are ours (standard silent). Rule: insert before the frame's first packet when that packet's T-STD arrival time (PCR interpolation, R-ISO13818-043) is >= PTS - 1 s + 10 ms; otherwise insert before the first later input packet whose arrival time is >= PTS - 1 s + 10 ms. The last metadata packet must arrive by PTS - 1 ms (TB_n drain at 100 Mbit/s takes 41 us). AUs whose PTS lies across a time-base discontinuity from the insertion point are not inserted (R-ISO13818-031).

D-ISO13818-15. **Rate modes and PCR.** Vbr insertion leaves every PCR value and PCR-bearing packet unchanged; the T-STD rate of the affected PCR interval simply rises (R-ISO13818-043), which is conformant for a single-program TS. For a multi-program TS with independent time bases it cannot be made consistent (R-ISO13818-044): the injector warns and recommends Cbr { replace_nulls }. Cbr never moves a PCR-bearing packet (R-ISO13818-040, R-ISO13818-172). OPCR, TEI and duplicates in the input are passed through unchanged (R-ISO13818-027, R-ISO13818-003, R-ISO13818-011).

D-ISO13818-16. **Muxer defaults (later phase).** PCR on the video PID, in the adaptation field of video packets, every 40 ms by default (hard limit 100 ms, R-ISO13818-045); when no video packet is due, an adaptation-field-only packet on the PCR_PID (AFC '10', length 183, CC not incremented, R-ISO13818-010). PAT and PMT every 100 ms by default (standard silent, R-ISO13818-076; FFmpeg's PAT_RETRANS_TIME is 100 ms). Mux delay default 0.7 s (FFmpeg's default max_delay), never above 1 s for metadata/audio/MPEG-2 video or 10 s for AVC/HEVC. PTS/DTS from the input timestamps; every AVC/HEVC access unit gets an AUD if missing (R-ISO13818-166, R-ISO13818-169). PMT PID and first ES PID follow FFmpeg's defaults (0x1000 and 0x0100) unless configured.

D-ISO13818-17. **PTS arithmetic.** All PTS values are 33-bit and compared modulo 2^33 (R-ISO13818-065): the difference a - b is taken in (-2^32, 2^32]. Wrap-around (about 26.5 h) is not a discontinuity.

D-ISO13818-18. **KLV rate and PTS spacing.** The 0.7 s PTS spacing rule covers only video and audio (R-ISO13818-069); 13818 sets no minimum rate or maximum PTS gap for metadata or private data. Rate policy is MISB's (other topics); the checker does not apply 2.7.4 to 0x15/0x06 PIDs.

D-ISO13818-19. **T-STD for async KLV (0x06) in the checker.** 13818 models private data only up to the demultiplexer (R-ISO13818-163) and gives no Rx_n for it. The checker therefore checks only the TS-level rules (CC, PUSI, PES syntax, PES_packet_length != 0) and reports buffer behaviour as "not modelled"; if a metadata_STD_descriptor happens to be attached to a 0x06 stream it uses its Rx_n/BS_n for an informative TB/B check. The 1 s delay rule needs a PTS and does not apply.

D-ISO13818-20. **PSI repetition.** Standard silent (R-ISO13818-076). Injector: whatever the input does (each input PMT occurrence becomes an output PMT occurrence). Muxer: 100 ms (configurable). The checker reports the measured maximum PAT/PMT interval and flags > 500 ms only as a warning (DVB/ATSC practice; not a 13818 rule and not verified from a document in `specs/src`).

D-ISO13818-21. **Delivery before decode for PSI.** The checker models TB_sys (512 bytes, Rx_sys 1 Mbit/s, R-ISO13818-151) and B_sys (1536 bytes, Rsys) for PAT and the program's PMT PID (R-ISO13818-153, R-ISO13818-154, R-ISO13818-156). A rewritten PMT longer than the input's can push TB_sys toward overflow when its packets are back to back at high transport rates; the injector spaces extra PMT packets if the model says so.

## 6. Unresolved

1. **metadata_input_leak_rate and metadata_buffer_size have no normative value.** 13818 only defines their meaning; ST 1402.2 says "determined by encoder". The defaults in D-ISO13818-04 (100 Mbit/s, 128 KiB) are our policy, justified by the T-STD arithmetic, with no reference implementation to compare against (FFmpeg and GStreamer write no metadata_STD_descriptor). They stay configurable.
2. **Whether PES header bytes enter the metadata B_n** (2.12.10 is silent). Resolved conservatively for the checker (D-ISO13818-05); a stricter or looser reading would only change computed fullness by about 19 bytes per PES.
3. **2.7.5 "PTS for the first access unit of each elementary stream" versus async KLV without PTS.** Resolved by reading the rule as not applicable to private data (D-ISO13818-09); the text itself does not carve out private streams.
4. **No T-STD for private data (0x06).** Annex H (informative) leaves it to private parties; nothing to check beyond the demultiplexer (D-ISO13818-19).
5. **PSI repetition and PCR practice limits** (100 ms / 500 ms PAT-PMT, 40 ms PCR) come from DVB/ATSC/ETSI TR 101 290 practice that is not in `specs/src`; they are used only as defaults and warnings, never as 13818 rules.
6. **Tables and equations from the PDF were not visually verified** (no PDF renderer available). Field widths of Tables 2-84, 2-87, 2-89, 2-108 come from the extracted column order and agree with ST 1402.2 Appendix B and both reference implementations; the garbled equations (2-1 to 2-5, 2-7, 2-11, Rx_n values) were reconstructed from the surrounding prose and their well-known form. A human should glance at PDF pages 31-33, 109-113 and 151-152 before phase 2 freezes the encoders.
7. **GStreamer interval defaults** (`TSMUX_DEFAULT_PAT_INTERVAL`, `TSMUX_DEFAULT_PCR_INTERVAL`) are defined in `tsmux.h`, which is not in `specs/ref`, so they are not recorded here.
8. **Registration descriptor on sync streams** is a compatibility choice outside 13818 (D-ISO13818-01); the `st1402` topic should confirm or override it.
